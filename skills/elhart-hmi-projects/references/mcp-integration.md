# Работа через Elhart MCP

Поставляемая версия MCP — 0.6.0 (86 инструментов). Исторические подтверждения
ниже относятся к 0.5.0; USB-загрузка 0.6.0 описана отдельно в
[процедуре панели](../../../docs/panel-download.md).
Нативные подтверждения относятся к ELHART HMI
Soft 3.0.15569.0. Исходники и установка:
[IlistTeam/elhart-hmi-mcp](https://github.com/IlistTeam/elhart-hmi-mcp),
[инструкции установки](https://github.com/IlistTeam/elhart-hmi-mcp/blob/main/docs/elhart-installation.md),
[границы испытаний](https://github.com/IlistTeam/elhart-hmi-mcp/blob/main/docs/elhart-validation.md).
План адаптации выполнен для указанных версии и сценариев; экспериментальные
инструменты не считай проверенными по одному наличию в каталоге.

## Соединение и работа с проектом

Проверь `fstudio_health`, профиль Elhart и фактическую версию DTO.
`compiler_available=false` отдельного DTO-моста не означает, что компилятора
в редакторе нет. Затем проверь плагин через `fstudio_visible_state`:
сверь workspace и путь проекта. Это отдельное соединение.
Устанавливай Python и DLL плагина согласованно; занятая DLL обновляется
после сохранения и закрытия загрузившего её экземпляра и повторной установки.

При запуске нового редактора через `fstudio_visible_start` передавай явный
сохранённый проект, чтобы автозагрузка предыдущего занятого проекта не
создавала предупреждение. Живой endpoint переиспользуется; старт не является
переключением проекта. Для переключения используй штатные операции проекта.

Выбери панель из `fstudio_list_models`. Проверенный профиль ECP10:
F010 / ID2050 / 1024×768 / a8, OEM119. Шаблон `.tpl` содержит проект,
OEM `.ptpl` является накладкой. LB/LW создавай штатной фабрикой адресов;
GUID устройства конкретен для проекта, Raw LW не равен каталожному 255.

Сохраняй текущий проект перед закрытием или сменой. После открытия заново
получай новые `$ref`: старые ссылки недействительны.
Задача с job_id и queued/running ещё не имеет подтверждённого результата.
Опрашивай тот же job_id через `fstudio_visible_job` до completed/failed.
Если запись наблюдалась слишком долго, сначала прочитай её задачу и модель;
повтор записи может создать дубликаты.

## Компоненты и устойчивое редактирование

Начни с `fstudio_canvas_snapshot`: имя страницы, размер, UUID компонентов,
имена и фактические bounds. Стабильное имя должно совпасть ровно с одним
компонентом. Совпавший изменяй через model_set_many/apply_many, отсутствующий
создавай, неоднозначный сначала разрешай. `canvas_create_many` только создаёт
и отвергает существующие имена; это не upsert.

Русский текст задавай через `StaticTextTool` с text/text_style. Числовые поля
создавай `NumericCharTool` с нужной операцией, типом, полной парой ограничений
и локальными адресами. Подписи, значения, кнопки и индикация остаются нативными.
Для пустой кнопки проверены `canvas_configure_bit_switch` и
`canvas_configure_bit_indicator`: действие и два состояния на локальном бите.
Существующие действия и условия сохраняются; инициализаторы отказываются
их заменять. Новые или более сложные состояния требуют отдельной проверки.

Для пустого индикатора на текущей странице проверен
`canvas_configure_word_indicator`: LW с UInt16, равенство 0/1 и резервное
ShowErrorState, три изображения 64×64, три графических/текстовых состояния,
пустые подписи и квадратные bounds. Смена трёх состояний подтверждена оператором
в симуляторе. Для знакового числового поля
согласуй NormalData.DataType и ReadAddress.Raw.DataType; проверено сохранение
Int16, IsShowZero и ограничений −32768…32767. Оператор подтвердил оба крайних
значения и отклонение 32768/−32769. Для нового проекта повтори его приёмку.

Для пустой картинки в Elhart проверен `fstudio_import_image`: native
LoadFromFile задаёт PictureOrigin=File и сохраняет источник без ручного
исправления XML. Задавай alpha и пропорции; сохраняй и повторно открывай.
Для перехода пустой Switch на существующую Basic-страницу проверен
`canvas_configure_navigation`; цель — UUID, а не номер в списке компонентов.
Проверены `canvas_history`, `canvas_undo`, `canvas_redo` и сохранение UUID
пакета. После undo/redo получай свежий снимок. Заверши или отбрось черновики
перед отменой; не теряй их из-за неизвестного состояния.

Точечный ремонт нативного формата выполняй закрыв целевой проект,
с `scripts/native_xml.py`, установленными DTO и проверкой QName/порядка полей.
Этот путь сохраняется для подтверждённых специальных случаев.

## Компиляция и симулятор

Сохрани проект, запусти `fstudio_build_start`, опрашивай тот же build_id через
`fstudio_build_status`. Принимай успех только с compiler_success=true,
сохранностью исходников, результатами сборки и cleanup_complete=true.
Читай нативную диагностику, журнал и хеши. Отрицательный ответ компилятора
даёт failed; статус Task публикуется отдельно. Ошибку проекта исправляй
и повторяй ту же полную сборку. Не подменяй её десериализацией DTO.

`fstudio_build_cancel` сначала передаёт нативный токен; через три секунды
может завершить собственное дерево изолированного worker, если нативная
задача ещё работает. Этот режим указан в результате. Естественное завершение
сохраняет реальный ответ. После отмены продолжай читать состояние до конца
очистки; частичные артефакты не являются готовой программой панели.

`fstudio_simulation_start` экспериментален: запускает офлайн-среду и сохраняет
RW/рецепты/историю. `simulation_state` доступен без ожидания UI; нативные
флаги датированы, новые PID являются кандидатами. Появление FCS/FSGUI
подтверждает запуск процессов, а не картинку или нажатия. Нужны снимки
реального приложения, проверка числового ввода, состояний, переходов и времени.
Физическая панель и связь с PLC остаются отдельными проверками.

При недоступном захвате продолжай применимые проверки и явно сохраняй
незавершённую визуальную/интерактивную приёмку. Закрой собственные ненужные
тестовые окна после проверки. Для SLM используй существующие проверки
макроса и времени; карта и блокировки примера не универсальны.

## Итог приёмки 15.10.2026

План адаптации выполнен для Elhart 3.0.15569.0/ECP-10, MCP 0.5.0.
Нативные плагин/сохранение/повторное открытие/полная сборка проверены отдельно
от интерфейса. Оператор подтвердил Int16 0/−123/−32768/32767, отклонение
32768/−32769, PNG alpha, состояния и переходы представительного экрана.

SLM прошёл цикл около 56 реальных секунд после исправления временной базы,
ручное управление, аварийные блокировки, настройки, калибровку без дублей,
журнал/фактический CSV, очистку около 3 секунд и запрет азота для титана.
Получены настоящие снимки пяти страниц и представительного экрана.
Win32/ARM, DTO и C-регрессии дополняют эти ручные наблюдения.

Computer Use не получает кадр; операторская приёмка не выдаётся за его
исправление. Точность монотонного секундомера, панель и PLC не подтверждены.
Полный отчёт и границы:
[итог Elhart MCP](https://github.com/IlistTeam/elhart-hmi-mcp/blob/main/docs/elhart-final-results.md).
