# Проверка упаковки ELHART HMI 0.6.0

Дата: 27.10.2026. Проверка Windows без запуска редактора/симулятора/панели.

- `python -m unittest discover -s tests`: 68 тестов, успешно, 1 пропуск.
- Новые тесты проверяют согласованность переносимого и совместимого манифестов,
  комплектность ресурсов навыка, перенесённый launcher и двусторонний stdio
  с fixture-сервером. Это проверка PowerShell-запуска, не нативного DTO-моста.
- `skills/elhart-hmi-projects/scripts/test_helpers.py`: успешно, QName
  round-trip, отказ повреждённому primitive и перезаписи существующего результата.
- `quick_validate.py` для bundled-навыка: успешно.
- Существующие проверки старого FStudio ZIP прошли после переноса upstream-навыка.
- Windows CI выявил сравнение длинного пути профиля с его 8.3-алиасом.
  Launcher теперь проверяет идентичность workspace/Bin через `os.path.samefile`
  и физическую границу кэша через `realpath`; тест пути OEM overlay также
  проверяет идентичность файла вместо написания пути.
- `git diff --check`: успешно.

`test_system_validation.py` и `test_control_validation.py` запущены, но не прошли:
в этой среде нет `Flexem.Studio.Dtos.dll` по стандартному пути ELHART HMI Soft.
Их исключили из GitHub host CI: на обычном runner нет библиотек производителя.
Это ограничение среды, а не подтверждение работоспособности нативных сценариев.
Реальный запуск нового installed-пакета с DTO-мостом и редактором здесь не проверен.
Прежние результаты нативной приёмки сохранены отдельно и не переобозначены.
