# Установка и диагностика Elhart MCP

Текущая интеграция: MCP 0.5.0, ELHART HMI Soft 3.0.15569.0, Windows,
Python 3.11+, .NET Framework 4.x, x86. Установленные библиотеки и шаблоны
производителя используются локально и не распространяются с исходниками.

## Сборка и настройка

Получите исходники форка, выберите короткий путь к рабочей папке проектов.
Пример ниже предполагает, что текущий каталог — корень репозитория.
Проверенная адаптация опубликована в ветке `feature/elhart-adaptation`
([PR №1](https://github.com/IlistTeam/elhart-hmi-mcp/pull/1)); до включения
изменений в main используйте эту ветку:

```powershell
git clone --branch feature/elhart-adaptation https://github.com/IlistTeam/elhart-hmi-mcp.git
cd elhart-hmi-mcp
```

```powershell
python --version
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\install-visible-host.ps1 -Workspace C:\MCP\elhart-hmi-mcp\projects -Profile elhart
```

Для нестандартной установки передайте `-FStudioBin` в build.ps1,
`-FStudioRoot` в install-visible-host.ps1 и `--studio-bin` серверу.
Пути workspace и Bin сервера и плагина должны совпадать.
Параметр ExecutionPolicy относится только к процессу запуска скрипта.

В [mcp.example.json](../mcp.example.json) замените путь к репозиторию
и рабочей папке. Если команда python недоступна клиенту, укажите абсолютный
путь к python.exe. Добавьте эту конфигурацию в MCP-клиент с транспортом stdio.

Сначала проверьте `fstudio_health`, `fstudio_capabilities` и
`fstudio_list_models`. Это проверяет отдельный DTO-мост, а не подключение
к работающему редактору. Для плагина нужны `fstudio_visible_start` и
`fstudio_visible_state`. При запуске передавайте явный путь к сохранённому
тестовому проекту: автозагрузка предыдущего проекта может открыть предупреждение,
если он уже занят другим экземпляром редактора.

Первый visible_state проверяет контракты установленного SDK. Результат
native_contracts доступен в health плагина; fstudio_visible_contracts
повторяет проверку без изменения проекта. compatible подтверждает только
сигнатуры типов, методов и конструктора, а не внешний вид или работу кнопок.

Не считайте список инструментов или PID доказательством исправной работы.
Сверяйте путь проекта, исполняемый файл, профиль, версию DTO и состояние задачи.
При неизвестном исходе записи опрашивайте исходный job_id и читайте модель
перед дальнейшими изменениями; повтор записи может создать дубликаты.

## Обновление

Сохраните проекты и закройте экземпляр, который загрузил старый плагин.
Повторите сборку и install-visible-host.ps1. Если DLL занята, установщик
сохраняет FStudioMcp.Visible.next.dll и pending-update.json: текущий редактор
продолжает использовать старый код. После закрытия выполните установщик ещё
раз и только затем запустите редактор с новым плагином.

Не завершайте чужой редактор принудительно для обновления. Не изменяйте
рабочую папку существующего endpoint, чтобы обойти ограничения доступа.

## Нативные испытания

```powershell
python -m unittest discover -s tests
python tests\elhart_native_smoke.py --name Acceptance01 --widgets --build
python tests\elhart_native_smoke.py --name Acceptance02 --widgets --extended --build --from-project projects\Acceptance01\Acceptance01.fsprj
python tests\native_connection.py Connection03 projects\Acceptance02\Acceptance02.fsprj
python tests\native_build_comparison.py BuildCompare04 projects\Acceptance02\Acceptance02.fsprj
```

Каждое имя испытания должно быть новым. Сценарий создаёт отдельный проект
через нативный мастер, сохраняет, повторно открывает и компилирует снимок.
В finally он сохраняет и закрывает только собственный редактор и потомков.
При невозможности безопасного закрытия процесс оставляется для восстановления,
а следующий тест отказывается запускать ещё один экземпляр.
Отчёт хранится в artifacts/elhart-smoke/<имя>/report.json.

`--extended` проверяет прозрачный PNG, нативное действие перехода,
undo/redo, повторное изменение по имени и отказ от повторного создания.
Для Elhart изображение импортируется через LoadFromFile, без исправления XML.

native_connection проверяет смену двух копий проекта и восстановление исходной
задачи после тайм-аута наблюдения без повторной записи. native_build_comparison
сравнивает нативную сборку внутри редактора с изолированной: каждый путь должен
завершиться успешно, ресурсы совпасть, данные и исходник сохраниться. Различие
fshmi.bin фиксируется отдельно; успешное сравнение не означает эквивалентность
этого бинарника. Промежуточный Subbin исключён из входов снимка.

`--simulate` подтверждает запуск FCS/FSGUI и затем закрывает тестовую группу.
Он не выполняет визуальную или интерактивную приёмку. Для неё нужен отдельный
контролируемый сеанс: снимки реального приложения, ввод числа, нажатия,
смена состояний и переходы. После проверки закрывайте ненужные окна.

## Диагностика

- Unsupported DTO version: чтение метаданных возможно, изменения отклонены;
  требуется новая проверка контрактов и нативных сценариев этой версии.
- Pipe unavailable при живом процессе: не запускайте дубликат; проверьте
  исходный процесс, endpoint и visible-host.log.
- Проект вне workspace: проверьте конфигурацию и используйте разрешённую копию.
- Предупреждение «файл проекта был открыт»: закройте ненужный экземпляр,
  который держит этот проект, предварительно сохранив изменения.
- Ошибка сборки: читайте compiler_success, native_task_status, диагностику,
  журнал конкретной сборки, source_unchanged и cleanup_complete.
- Нативный флаг симуляции: это датированное наблюдение. Новые PID в статусе
  являются кандидатами; они не доказывают показ экрана или работу кнопок.

Исторические проверки FStudio не являются проверками Elhart.
Актуальные подтверждения и ограничения — в
[отчёте](elhart-validation.md), полный объём приёмки — в [плане](../PLAN.md).

## Поставка исходников

`python package-skill.py --profile elhart` создаёт Elhart_MCP_source.zip.
Он содержит Python, C#, скрипты сборки, пример конфигурации, лицензию и
документацию. В архиве нет DLL, шаблонов производителя, проектов пользователя
или локальных настроек. Мост и плагин собираются после распаковки.
Отдельный навык `elhart-hmi-projects` сохраняется в своём репозитории;
его пример SLM не вкладывается в исходники MCP.
Для прежней структуры FStudio доступен `--profile fstudio`.

Проверено извлечение в отдельную чистую папку, сборка и реальный запуск
stdio MCP, загрузка плагина, чтение копии проекта/снимка страницы через
tools/call, сохранение и закрытие тестового редактора. Версии и области
проверки перечислены в [таблице возможностей](elhart-capabilities.md).
